# 阅读报告 → 分享卡片

用于把已有阅读报告和对应真实记录做成分享图片与配文。默认平台为小红书，默认视觉为 [全幅主题阅读卡](default-share-design.md)，不需要用户额外配置。它是可选衍生输出，不是将私人阅读库整体变成公开内容。预览后用户明确要求发送时，才按 [社交平台交付](social-delivery.md) 上传到用户自己的草稿箱。文本记录与选句不依赖外部技能；视觉规划优先复用实际可用的专业设计 Skill，不默认套自写实验模板。

## 报告完成后的入口

每份阅读报告完成交付后主动询问一次是否生成适合小红书的分享图和文案；先问，不先制作。用户已要求分享就直接制作，明确只要文字、已拒绝本次分享或已关闭询问时跳过。普通记笔记、回顾和小修报告不触发。用户说“要”，即采用下面的默认设计、选句和文案规则，不再追问平台、字体、张数或账号配置；真正影响正确归属的来源缺口才需澄清。

## 输入与选句

先读对应报告与主档的相关记录，沿用已有来源 ID 和记录 ID。报告只负责帮助筛选，原文引句仍须回到实际可见的原来源核对。只有报告、没有主档时可以整理报告中的观点，但不可宣称已经验证原文引句。无需重新读取无关私人档案。

- 用户指定金句：保留原句、语气和疑问形式；指定样式与次序优先。只调整换行，不擅自改写。来源不明时先找可访问的依据；仍找不到就明确待核，可先交选句或排版草案，不能生成冒充已核引文的成品。
- 自动选句：从真实记录中挑选可独立理解、与本期个人思考相关、表达具体且适合手机阅读的句子。一般选3—5句，材料少就少做，不凑数。不因追求“金句感”加重判断、去掉“可能”，或把问题改成结论。
- 有后续澄清时，按最新澄清理解原意；旧表达只有连同必要语境才能使用。AI误解被纠正，不写成读者的认知反转。
- 原句太长时可以拆卡或选连续片段，不能静默删改成新引文。确需压缩，改用“读者观点整理”，保留原表达供回查；指定原句则先交可读排版或说明长度问题。

每句在内部回查清单中必须明确以下四种身份之一；身份用于选句和核对，不要求作为图上的标签。分享卡默认以阅读记录中的感想、金句或关键信息为主体大字，底部仅写对应文章标题。省略“读者原话”“观点整理”“读这篇时的感想”“据读者记录整理”等流程说明，记录号和证据定位保留在私有清单。书刊与期号可作为组图的安静页眉。

| kind | 内部分类 | 核对要求 |
| --- | --- | --- |
| `source_quote` | 原文摘录 | 原作者或实际说话人（已核时）、篇目、书刊/版本、已知页码留作回查。受访者的话不能署给记者。 |
| `reader_quote` | 读者原话 | 逐字对应读者记录，不能把它署给文章作者或加成原文引句。 |
| `reader_paraphrase` | 读者观点整理 | 能回到原表达，不加原文引号，不提升判断强度。 |
| `ai_summary` | AI 归纳 | 不能当成读者亲口说过；默认不从未经读者接受的AI延伸中选句。用户需要时另行明确其性质。 |

每张卡均显示实际篇目；杂志只标整期名称不够。书籍可用章节，确无篇章信息时以实际书名为来源。综合多篇的卡片列出各篇，放不下就拆卡，不能随意只署其中一篇。未知作者、页码省略，不猜测，不把记录号冒充页码。

默认省略“故事与价格”这类额外主题小标题和对应的英文副标题，直接进入主体金句。全幅主题底图、书刊与期号页眉、主体金句、底部篇目构成主要层级；用户可另选纯色等样式。

## 设计交接与内容安排

先读取默认设计并检查宿主已有设计 Skill。书摘、读者感想和杂志式组图优先参考 `guizang-social-card-skill` 的层级、构图与检查规则；插画、漫画或信息图表达可评估 `baoyu-xhs-images`。读取选中 Skill 的实际入口和必要参考，不仅在提示词里写一句“参考某某风格”。先交锁定文案、句子身份与出处；默认由宿主可用生图工具一次生成完整图文，专业 Skill 可负责规划，不把规划说成它的模板渲染。用户参考图或明确设计要求优先。

没有专业设计 Skill 时仍可按随包默认设计使用宿主现有生图工具，明确实际工具；不要求用户安装特定设计 Skill。连生图能力也不可用时，交付选句、配文和设计交接单，图片标待制作；不得默默调用下面的实验模板代替。只在用户明确选择基础模板时才使用自带渲染器。不擅自安装依赖、改写全局技能或扩大发布权限。

一张图只承载一个核心表达。默认一张系列封面加若干内容卡，不强迫凑固定页数。提炼标题属于整理文案，不能伪装成原文引句。书刊封面、作者照片或扫描页依实际素材与所选技能处理；不伪造封面，不照搬出版物版式。每张图保留可读的出处。

## 每组必交的分享文案

默认交付一个可直接使用的小红书标题、一份完整正文及3—6个真实相关话题；用户不必另提“写配文”。标题简短具体，以当前平台工具能核查的限制为准，不编造“必看”“读完逆袭”等承诺。正文包含实际书刊/版本、真实记录覆盖范围内的个人思考、与组图呼应的简短观点和自然收尾；可以用一个真正在意的问题邀请讨论，不机械加关注引导。

配文保留疑问和限定词，不编阅读经历、评分或读完整部作品的经历。明确“卡片整理自我的阅读记录，篇目见各图底部”；生成背景时补一句“配图为AI生成的主题示意图”。这些说明放在配文，不重新塞进卡片主体。纯色精确排字或用户照片按真实情况说明，不能虚称使用AI照片。平台AI声明与这句文字说明分别处理，不能互相替代。

标题、正文、话题分区展示，便于复制；同样内容保存为实际输出目录里的 `分享文案.md` 或等价可下载文本。话题来自作品、主题和阅读方式，不凭空加“热门”或无关流量词；实际上传能选择真实话题时再核验绑定。

## 全幅底图与字体

底图默认铺满整张卡片，页眉、金句与底部篇目直接排在图片上。不要使用“中央图片加外圈纯色”的结构；文字安全边距用于排字，不应变成图片外框。按默认设计与所选设计 Skill 的图片压字规则处理主体避让与清晰度。

用户另选纯色或中央图块时才采用对应结构；中央含字图块可按需单独导出，完整分享卡仍须在底部显示篇目。此选择交给当前专业设计 Skill 执行，不要求实验渲染器支持底图。

纯色适合长句和信息密度较高的卡片，用户选择时可用；默认全幅底图不能为了装饰掩盖文字。默认一次生成含文字图片，保留全部锁定文字，出图后逐字核对金句、标点、篇目与期号；不把提示词中的文字正确当作图片已正确。生成字形通常没有可编辑字体文件，改字可能需要重生；需频繁改字时可选择实际可用的特色字体精确排版。记录真实出图工具，不能将图片生成器的输出称为已调用其他设计 Skill 的渲染。底图应有清楚的文字区域，文字避开人物、产品等主体，并在手机宽度下检查。不要把杂志扫描页直接当作可随意分享的装饰背景。

生成或示意素材须在私有清单记录性质及来源，交付说明或配文说明其为示意，不能冒充文章里的实拍现场、门店或产品证据。用户给定图片优先，缺少清楚的文字区域时改构图、换图或退回纯色。同一句话做纯色与底图对照时保留相同文字和出处，便于判断视觉差异。底图生成多一个制作与检查环节，费用和耗时按实际工具记录，未知不写精确数字。

字体不固定为某一款，也不固定为手写体。按每张内容的主题、语气、句子长度和底图选择适合的字形、笔触、字重及排字节奏；已接受的样张用于确认视觉气质，不作为所有卡片必须套用的字体模板。同组图片保持色调、出处层级与可读性协调，可有节制地变化字体；避免随机混搭、单张堆叠过多字体，或让装饰性损害辨认。用户指定字体时优先遵从。

使用本地字体时先确认实际可用字体和最终渲染字体，不能只改字体名称就称已生效；不把系统字体打包分发。生成式字形同样要检查字形清楚、中文正确。需要对照时保持文案和布局一致再比较字体。长金句用语义换行、字号与正文到篇目栏的间距调整疏密，避免正文结束后留一大片无用途空白；不要靠补装饰或新增无据文字填满。用户要求的字体改造记录为所选设计 Skill 的任务适配，不冒充其原生标准样式，也不自动覆盖以后所有卡片的字体。

## 实验模板（仅明确选择时使用）

以下是早期技术原型，保留用于明确选择的基础排版，不作为默认视觉标准。这里的1080×1440是本套实验模板的画布选择，不是平台永久规格或审核保证。

| 样式 | 视觉 | 适合 |
| --- | --- | --- |
| `editorial` 杂志批注 | 暖白纸色、衬线大字、砖红细线、清晰篇目栏 | 基础文字卡测试 |
| `minimal` 留白笔记 | 浅鼠尾草色、无衬线字、细分隔线 | 清楚的观点、问题和知识类阅读 |
| `night` 夜读摘句 | 深墨色、暖白文字、少量杏色强调 | 较短、有情绪或余味的句子 |

同一组沿用一种样式，比较样式时用同一句话出样，避免内容差异掩盖样式差异。实验模板命名与外部 Skill 的同名风格没有继承关系，不能把它们称为归藏或宝玉的效果。

## 工具与交付

默认按全幅主题设计实际生成图文，记录设计规划来源、实际图片工具、布局与输出。用户明确选择实验模板且有本地代码能力时，才使用 `scripts/render-share-cards.mjs`。它的基础模式只需 Node.js，生成卡片 HTML、总预览和私有回查清单；PNG 模式另外需要宿主已安装的 Playwright 与可用 Chromium/Chrome。命令参数见 `--help`。先检查能力，不自动安装浏览器或依赖，不固定某个用户的机器路径。

可参考 `assets/share-cards.example.json` 的虚构例子创建输入。输入、成品及回查清单放在实际私有输出位置，不能写进公开 Skill 仓库。渲染器也会拒绝把输出写入自身 Skill 包。`evidence.text` 保存已实际读取的证据片段，`evidence.locator` 保存回查入口；它们只进入私有清单，不嵌入图片和HTML。

```bash
node scripts/render-share-cards.mjs --input /private/path/cards.json --output /private/path/share-pack
node scripts/render-share-cards.mjs --input /private/path/cards.json --output /private/path/share-pack --png
```

安装在宿主其他位置的 Playwright 可用 `--playwright-module /absolute/path/to/playwright/index.mjs` 指定；浏览器默认用 Playwright 已安装的 Chromium，也可用 `--channel chrome` 选择已有Chrome。依赖缺失时仍可交付HTML，但须明确“PNG未生成”，不能把网页、SVG或提示词称为可直接上传的图片。

选择了需要特定渲染器的外部 Skill 却缺其能力时，明确该路线未完成；可用默认整体生图路线就说明实际路线后继续，只有实验模板需用户另选。没有任何出图能力时标记图片待制作，不虚报已出图。中文准确性与出处不能因使用生成式图像而免检。

## 核验与归档

1. 内容：逐句核对kind、证据、篇目、署名、限定词与后续澄清。脚本只能检查字段与字符串匹配，不能证明来源真实或解释正确。
2. 图片：核实PNG真实存在、尺寸正确；逐张查看中文、换行、出处和底部安全区，缩到手机宽度检查可读性。溢出应拆卡或重排，不能靠无限缩小字体解决。
3. 分享：通常只交付 `images/` 中的PNG及选定配文。`private-manifest.json` 含原记录、私有链接，不纳入公开分享包；HTML只含图上文案，但仍需按实际内容检查隐私。
4. 归档：报告、卡片、配文、回查清单作为同一对象的衍生产物登记，依宿主现有库规则保存；不新建第二份阅读主档。默认值不必写一份个人配置才能使用；用户明确改变长期偏好时才局部写入私有配置，保留“不出图/只出文字”的覆盖方式。
5. 预览：在会话中直接展示实际图片，优先原生图片输出或可点击的图片嵌入，不能只给目录或文件路径；有多张时交完整顺序，可先总览再逐张预览。宿主不能内嵌时提供其可用的预览/下载入口并说明。同步展示完整可复制文案与“保存到小红书草稿箱”的下一步。
6. 回报：分别说明选句、PNG、文案和长期归档的真实状态；HTML仅明确选择模板时涉及。制作失败须报告错误；修正使用新版本目录或保留旧版本。用户未要求发送则停在交付，明确要求后按社交平台交付步骤继续；不自动设置公开链接。
