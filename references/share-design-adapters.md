# 分享卡片的设计 Skill 接入

## 分工

Readmate 负责阅读主档、文本报告、候选金句、用户指定金句、原意、句子身份和来源篇目。专业设计 Skill 负责视觉方向、组图节奏、版式、字体、素材处理与渲染。出图后 Readmate 核对文字和出处，并将产物关联回原阅读对象。

默认顺序：报告 → 询问分享 → 有据选句与配文 → [默认全幅主题设计](default-share-design.md) → 规划与整体图文生成 → 看图核对 → 会话预览与衍生归档。用户要求发送后再进入 [社交平台交付](social-delivery.md)。不要让视觉优化反向修改锁定的引文，也不要把同一句内容换三种底色称为完整设计探索。

默认设计继承已确认组图的全幅主题背景与内容驱动字体，不需要每次重新选择第三方设计方案。宿主有专业设计 Skill 时实际读取适用规则，用于规划或渲染，并如实区分这两个角色。没有这些 Skill 时，可直接按随包默认设计使用现有图片生成能力；它不依赖用户机器上特定的私人样张或字体。

## 最小交接单

交接在私有任务目录落盘，包含：

- 阅读对象/报告与记录定位符、对应记录编号；
- 目标平台、画布要求、受众与期望图片张数；
- 每张卡的文字、四类句子身份之一、具体篇目、书刊与版本、已核作者/页码；
- 哪些文字锁定不改，哪些标题允许另拟，用户指定的顺序、风格和金句；
- 字体方向由内容决定，不锁定某一款或一律手写；按主题、语气、句长和底图选择，组内保持整体协调，避免机械复用或随机混搭。已接受样张是气质参考，除非用户明确要求，不视为固定字体模板；
- 图上信息层级：主体大字呈现感想、金句或关键信息，底部仅呈现对应文章标题；kind、记录号和“读这篇时的感想”等流程说明保留内部，不作为可见标签；
- 实际可用的照片/截图，以及只能核对不能对外展示的材料；
- 视觉模式：默认全幅主题底图与文字一次生成，参考 `full-bleed-reading-v1`；用户可另选纯色、自己的图片或可编辑字层。记录图片来源、示意性质、主体位置和文字区域，底图不得改变锁定文案；
- 交付目录、拟采用设计 Skill、已读取的版本/路径、当前可用渲染工具。

让接收方在已选默认方向内按实际 Skill 规则规划页面，不强塞实验模板。涉及素材、确认、费用等步骤时，先看当前会话是否已明确，再按该 Skill 的具体要求处理；不能重复索取已有信息，也不能把“请考虑设计Skill”解释成安装所有候选、付费或发布的授权。

## Guizang 接入要点

实际采用前读取入口及 `style-system.md`、`theme-presets.md`、`layout-recipes.md`、`components.md`、`portrait-fill.md`、`production-workflow.md` 和 `qa-checklist.md` 中相关部分。候选结构包括 M04 Pull Quote、M11 Marginalia Essay、M13 Hero Question；版式ID是上游参考，不是Readmate新造的模板。

若采用 Guizang 模板渲染路线，实际出图应使用该 Skill 的种子模板及组件，而不只是借用名字。确认所需素材与授权范围；它的图片输入、视觉预览和自动检查节奏按当前入口执行。记录采用的主题、版式、模板版本与产物路径。默认整体生图路线只读取其设计规则用于规划时，明确写规划角色，另记真实图片工具；未真正用上游模板渲染过，不宣称该模板接入验证通过。

涉及图片压字时另读 `image-overlay.md`，按照片选取、主体避让和手机缩略图规则处理。先尝试无蒙版构图；没有合适文字区域时换图或改版，不用厚重蒙版强行盖住主体。默认页眉、正文与底部篇目直接排在全幅背景上，不变成“中央图块加外圈底色”。

研究副本只用于阅读和评估，不等于已安装到宿主技能目录。发布 Readmate 包时不自动把上游源码、字体、模板和私人样张打进去；按所选依赖的实际许可证与分发方式核对。当前 Guizang 仓库附 AGPL-3.0 及商业合作说明，不能把第三方设计能力宣称为 Readmate 自研。

## 回收与验收

回收设计 Skill 的实际输出和检查结果，再检查：锁定引文逐字一致、整理类型没有伪装成引文、读者感想未署给原作者、每张卡的篇目可见、已知限定词与澄清保留。原设计 Skill 的版面检查和 Readmate 的内容核对分别报告。

回查单记录 `design_preset`、`design_skill`（可为空）、`role`（planning/rendering）、`upstream_url`、`version_or_commit`、`image_tool`、`execution_status`、`layouts`、`outputs`、`content_check`、`visual_check`。只读过文档就写 `researched`；实际渲染后按证据填写，不把调研、安装、出图和验证混为完成。私有回查单不随图上传。
